## 2. 后续增强原则

- 先处理已交付页面的体验一致性，再增加新的业务能力。
- 保持模块化单体、SQLite 和本地文件存储，不因视觉优化提前扩容基础设施。
- 批次 13 不改变权限、状态机、计分、统计口径和接口字段。
- 优先复用现有设计变量和公共组件，避免为统一样式复制新的页面级规则。
- 先完成桌面端主流程，再验证窄屏；所有操作继续保留清晰的加载、失败、空状态和禁用反馈。
- 全文检索、文件预览、统计、SSO 和 AI 能力分别立项，不与批次 13 混做。

## 4. 批次 13：前端页面样式统一与体验优化（已完成）

### 4.1 问题定义

批次 8–11 以后新增的任务闭环、竞赛闭环、工作台和管理功能已经通过功能验收，但页面是在不同批次逐步叠加的：

- `TaskDetailView.vue`、`CompetitionDetailView.vue` 和 `AdminCompetitionsPanel.vue` 承载了较多状态与操作，信息层级和操作密度需要重新梳理。
- 任务、竞赛详情复用了以 `artifact-*` 命名的通用详情样式，视觉可以复用，但语义和维护边界不够清晰。
- 批次 8/9 的任务与竞赛样式追加在 `global.css` 现有响应式规则之后，窄屏表单、操作按钮、时间线和管理表格缺少同一套响应式收口。
- 卡片内边距、圆角、状态标签、区块标题、辅助说明、主次按钮和空状态需要统一标准。

### 4.2 页面范围

第一优先级：

- 任务详情：参与、提交、验收、竞赛评审、时间线和右侧操作区。
- 竞赛详情：任务清单、报名状态、排行榜和管理员入口。
- 管理页竞赛面板：竞赛列表、竞赛表单、任务配置、评审与结果发布弹窗。
- 探索页：个人待办、闭环统计与模块入口的层级关系。

联动检查：

- 任务列表与展品列表的筛选工具栏、表格或卡片、分页和空状态。
- 展品详情作为现有详情页视觉基准，确保任务与竞赛页面统一但不误改展品业务。
- 登录页、Issues 和知识库只做回归检查；没有明显不一致时不主动重做。

### 4.3 设计与实现边界

- 沿用 `variables.css` 中的颜色、字体、圆角、阴影和过渡变量；缺少的间距、控件高度或状态色先补公共变量，不散落硬编码。
- 统一页面头部、内容卡片、区块标题、元信息、状态标签、操作组、表单提示、错误提示、空状态和加载状态。
- 将跨展品、任务、竞赛复用的详情布局改为语义中立的公共类或公共组件；只在确有重复时抽取，不做一次性大重构。
- Element Plus 继续按组件逐个引入，不改为全局注册。
- 保留全部字段、按钮、条件、路由、API 调用和提交行为；不得以“简化界面”为由删除业务入口。
- 不新增后端接口、数据库迁移、权限规则、状态或统计口径。

### 4.4 建议文件范围

- `frontend/src/styles/variables.css`
- `frontend/src/styles/global.css`
- `frontend/src/components/common/` 下必要的公共展示组件
- `frontend/src/views/explore/ExploreView.vue`
- `frontend/src/views/tasks/TasksView.vue`
- `frontend/src/views/tasks/TaskDetailView.vue`
- `frontend/src/views/competitions/CompetitionDetailView.vue`
- `frontend/src/views/admin/AdminCompetitionsPanel.vue`
- `frontend/src/views/artifacts/ArtifactsView.vue`
- 上述页面与公共组件对应的测试文件

实际修改前先逐页截图和列出问题；未进入问题清单的文件不因顺手整理而修改。

### 4.5 建议实施顺序

1. 建立桌面端和窄屏基线截图，整理页面级问题清单与公共样式映射。
2. 补齐设计变量，统一公共页面骨架、卡片、状态和操作组。
3. 优化任务详情和竞赛详情的信息分组及响应式布局。
4. 优化竞赛管理面板的表格、弹窗表单和高密度操作区。
5. 收口探索页、列表筛选区、分页、空状态和错误状态。
6. 执行静态检查、组件测试、类型检查、生产构建和多角色浏览器回归。

### 4.6 验收标准

- 同类页面的内容宽度、标题层级、卡片边界、间距和状态颜色一致。
- 主操作、次操作和危险操作具有稳定且可区分的视觉层级。
- 长标题、长评语、空数据、错误提示、加载状态和按钮禁用状态不破坏布局。
- 任务提交、验收、竞赛评审和结果发布等表单在提交期间保持禁用，失败后恢复并保留输入。
- 1200px 桌面宽度和 640px 窄屏下无明显横向溢出；表格和操作区有明确的窄屏处理方式。
- 普通员工、任务发布人和系统管理员的既有入口及权限表现保持不变。
- `npm run test`、`npm run type-check`、`npm run build` 通过。
- 浏览器回归覆盖探索页、任务详情、竞赛详情、竞赛管理面板及任务/展品列表。

## 5. 批次 13 之后的候选顺序

批次 13 通过后，再按实际使用反馈逐项确认，不预先并行实施：

1. 展品正文检索和来源筛选增强。
2. 展品版本记录、文件预览和更细的下载控制。
3. 内容、贡献和闭环效率统计。
4. 公司 SSO 和外部通知。
5. 出现真实规模压力后再迁移 PostgreSQL、对象存储和后台队列。
6. 内容和评审数据稳定后再评估 AI 摘要、语义检索和辅助评审。
